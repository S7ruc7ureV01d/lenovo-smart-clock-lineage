# Lenovo Smart Clock (CD-24501F): LineageOS 16.0 port notes

Last updated: 2026-10-28

## Status

LineageOS 16.0 (Android 9) boots on slot B with the kernel built from source. Stock Android Things
stays on slot A as the fallback.

| Works | Notes |
|---|---|
| Display, GPU (PowerVR GE8300), HWC | Landscape like stock (rotation 1) |
| Touch (FT6336) | Follows the rotation |
| Wi-Fi (MT7668) | Scans and connects |
| Bluetooth (MT7668) | Turns on; audio profiles untested |
| Speaker | Amp set up by `smartclockd` |
| Volume keys, mute slider | `smartclockd`; Vol Up + Vol Down together = Power |
| adb (root on userdebug) | |

| Missing or untested | Notes |
|---|---|
| Ambient light (LTR578), accelerometer (BMA253) | Stock read them from the Things OEM app over I2C; no HAL yet, so auto-brightness is off |

## Stock software

- Android Things 1.1 on Android 8.1.0 (API 27), `OIM6.190107.007.A5`, patch level 2019-02-05
- Kernel 4.4.95 arm64 with a **32-bit-only userspace**. Source:
  [deadman96385/android_kernel_lenovo_mt8167s](https://github.com/deadman96385/android_kernel_lenovo_mt8167s)
- **Not Treble** (no VNDK), so no GSIs. Blobs come from the
  [stock dump](https://github.com/deadman96385/things_mt8167s_som_dump).
- A/B with system-as-root; the boot ramdisk is recovery
- Much of the hardware is driven by the Things OEM app (`/oem/app/com.google.android.things.sparrow.oem`)
  through the Things peripheral API, not by kernel drivers: speaker amp, mic ADC, volume keys,
  mute slider, light sensor, accelerometer.

### Partitions

| Partition | Size | Partition | Size |
|---|---|---|---|
| boot_a/_b | 32 MiB | system_a/_b | 512 MiB |
| vendor_a/_b | 64 MiB | oem_a/_b | 500 MiB |
| vbmeta_a/_b | 64 KiB | oem_bootloader_a/_b | 4 MiB |
| lk_a/_b | 384 KiB | tee_a/_b | 5 MiB |
| factory | 32 MiB | factory_bootloader | 16 MiB |
| metadata | 32 MiB | userdata | 5.0 GiB |
| misc | 1 MiB | proinfo, nvram, seccfg, para, frp, kb/dkb, logo | small |

**Never flash `oem_*`, `oem_bootloader_*`, `lk`, `tee` or the preloader** (`mmcblk0boot0`, whose
`force_ro` is already 0). The unlock guide says the stock firmware can't be restored once it's
lost, so back up every partition first. Such a backup holds per-device keys and identifiers:
keep it private.

## Boot chain (LK)

- **The board DTB lives in `oem_bootloader_<slot>`** (a `dt_table`, identical to `/oem/kernel.dtb`).
  LK ignores the DTB appended to the kernel, which is MediaTek's reference board (GT9157 touch, camera).
  So DT changes aren't possible without flashing `oem_bootloader_*`.
- **No early-mount fstab** in the DTB: `/vendor` mounts only at `mount_all`, so init rc, fstab and
  ueventd files live in the system root.
- **vbmeta:** LK marks the slot unbootable unless vbmeta has rollback index 1, flags 0, and
  descriptors for `oem_bootloader`, `oem` and `factory`. The build includes them from
  `prebuilt/vbmeta_stock_slot_b.img`, generated by `stockdesc.py` from stock vbmeta_b. Unlocked LK
  accepts the test key and hash mismatches (orange state). Always flash vbmeta together with the
  system image it was built with.
- **A/B metadata:** libavb `AvbABData` at misc+2048 (magic `\0AB0`, per slot {priority, tries,
  successful}, big-endian CRC32 over the first 28 bytes). LK's `set_active` can't revive an
  unbootable slot. Lineage's update_verifier marks the slot successful at late-fs, so a broken
  build doesn't fall back to slot A by itself.
- **Recovery is unreachable:** LK always passes `skip_initramfs`, so `adb reboot recovery` and a BCB
  `boot-recovery` both boot normal Lineage. To wipe /data, zero the first 4 KiB of userdata while it
  isn't mounted; fs_mgr's `formattable` then formats it on boot. This also wipes the encryption key
  location in `metadata`.
- **Fastboot:** LK stops reading USB when idle and hangs on the stock fastboot client's `getvar`
  queries. A command already waiting at enumeration works (`fastboot set_active a`, then plug in).
  `tools/fbmulti.py` (pyusb) sends download+flash directly and works reliably at about 28 MB/s;
  `max-download-size` is 96 MiB, so `tools/sparsesplit.py` splits `system.img`.

## Porting notes

What it took to get each piece working, and why.

**Build and size**
- `TARGET_ARCH := arm` with an arm64 kernel (`KERNEL_TOOLCHAIN` points at the aarch64 GCC);
  `TARGET_CPU_VARIANT := cortex-a53` (Pie has no A35 tuning).
- system is only 512 MiB: `common_mini_tablet_wifionly`, `PRODUCT_LOCALES := en_US` (it's also the
  aapt filter; setting only `PRODUCT_AAPT_CONFIG` does nothing), no dexpreopt, `removed-packages/`,
  and `BOARD_SYSTEMIMAGE_EXTFS_INODE_COUNT := 8192` (default inode tables waste ~31 MB).
- `PRODUCT_STATIC_BOOT_CONTROL_HAL` for update_engine_sideload.

**Core**
- `TARGET_USES_64_BIT_BINDER := true`: the kernel lacks `CONFIG_ANDROID_BINDER_IPC_32BIT`.
- Keymaster is Things-only (`vendor.google.iot.keymaster@3.1`): use the software keymaster 3.0.
- system_server blocks in `IMemtrack::getService()` unless the memtrack HAL service is built.
- adb: default.prop's `ro.adb.secure=1` wins, so the build host's key can be baked in as
  `/adb_keys` (copy it to the device tree as `adb_keys`, not committed). adb root needs
  `setprop persist.sys.root_access 3`, which a data wipe clears.
- The 4.4 kernel's FunctionFS AIO path panics under Pie's adbd/MTP; `sys.usb.ffs.aio_compat=1`
  makes them use the compat path.

**Display**
- The "frozen LENOVO logo" was `/oem/media/bootanimation.zip`, which bootanimation prefers, shown
  with the backlight LK leaves at 1/255. init mounts tmpfs over `/oem/media` and sets brightness 128.
- **libhwui aborts on GL errors** that the 8.1 PowerVR driver raises spuriously (`glFinish`
  `GL_INVALID_ENUM`), killing system_server on unlock and SystemUI/Launcher every frame.
  `patches/frameworks_base/` drops hwui's GLES validation and per-frame `GL_CHECKPOINT`s.
- Landscape: `persist.demo.rotationlock=true` pins every window, keyguard included, to rotation 1.
  Pie doesn't compute the rotation while the display comes up and nothing re-triggers it without a
  sensor, so init sets `user_rotation` once boot completes. `config_supportAutoRotation=false`
  alone makes the policy ignore `user_rotation`.
- Touch: stock's `CONFIG_TOUCHSCREEN_MTK_FTS_DIRECTORY` driver isn't in the source; the in-tree
  `CONFIG_TOUCHSCREEN_MTK_FT6336` matches the DT node.

**Connectivity**
- Stock's `wmt_loader` only insmods the Wi-Fi and BT modules from hardcoded stock paths
  (`/system/lib/modules/4.4.95+/...`). init loads them from `/vendor/lib/modules` instead.
- The 8.1 Wi-Fi HAL needs a `toString(sp<IWifiChipEventCallback>)` symbol that Pie's HIDL library
  dropped: `shims/` provides it via `TARGET_LD_SHIM_LIBS`.
- The stock Wi-Fi HAL rc has no capabilities, so the HAL can't bring wlan0 up: our copy adds
  `NET_ADMIN NET_RAW`.
- Pie drives wpa_supplicant over HIDL: AOSP-style service, `wpa_supplicant.conf` shipped by the
  device tree, `/data/vendor/wifi/wpa` created by init.
- Bluetooth needs `libbt-vendor.so` and `libbluetooth_mtk.so` from stock `/system/lib`.

**Audio**
- The stock HAL needs `libaudioroute` and `audio_mapping.xml` (stock `/system/etc`). Without the
  mapping it opens no PCM and crashes audioserver on the first write.
- **`smartclockd`** takes over the Things OEM app's hardware work: amp enable plus its register and
  EQ tables, mic ADC reset and setup, volume key GPIOs as uinput key events (both = Power), and the
  mute slider muting the ADC itself (page 0 reg 82). It polls the GPIOs and holds a wake lock (no
  battery, and nothing could wake it from suspend).
- Android 9 ignores volume presses during the first ~400 ms of the volume panel when nothing is
  playing (`VolumeController.suppressAdjustment`). That's AOSP behavior, not a dropped key.

**Things OEM app**
- `/oem/app` is hidden with tmpfs: sparrow.oem crash-loops without the Things framework.
- Its decompiled `Lenovo` and `OemPeripherals` classes are the reference for the hardware above.

## Build host

Pie needs an old toolchain environment (python2, ncurses5, `LC_ALL=C` for flex). On Arch, build in an
Ubuntu 18.04 distrobox. A shallow sync (`repo init --depth=1`, `repo sync -c`) is about 50 GB, plus
50–70 GB for `out/`; plan for 150+ GB free.
